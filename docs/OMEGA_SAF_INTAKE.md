# OMEGA v0.18.2 PRE-APK — SAF revisions and integration quarantine

Existing roadmap stages P12/P17/P18 are extended without introducing new stage IDs. No Android APK, Gradle, signing, device deployment, OCAF modification or CI invocation.

## Native owner-confirmed SAF revision

From the Omega native workflow screen, open **Utwórz zatwierdzoną wersję pliku SAF**. The new `NativeRevisionActivity` is non-exported, does not accept external intent parameters, uses `FLAG_SECURE` and clears visible state on stop. Choose an existing authorized `com.android.externalstorage.documents` tree with persisted read and write grants, `allowWrite`, and both `read_file` / `write_file` enabled. No new permission is requested. A filename in the root of the selected tree must be a regular `.txt`, `.md`, `.csv`, `.json` or `.log` with a bounded, non-ambiguous name; input and source are strictly decoded/encoded UTF-8, maximum 64 KiB each. No nested source paths, MediaStore or arbitrary providers. Enter replacement text, inspect the complete old/new strings, names and SHA-256 digests, then explicitly press **Zatwierdź zapis nowej kopii**. The original is not opened for writing. A newly generated `omega-<uuid>.txt` name is displayed before confirmation; even a non-TXT source yields a text revision with `.txt` suffix. The name must be absent and provider creation must return the expected direct child ID, distinct from the source; the fresh destination must be empty. The engine verifies the exact original identity/content, bound grant, and new content before claiming success. The plan lives in RAM, expires after 120 seconds, is consumed before any effect, and is reset when the screen reopens. Local UI confirmation is not an additional independent OS authentication factor: a previously authorized accessibility operator is already high-trust. No new remote MCP/OMAt operation or model-controlled approval is exposed.

`NativeAgentRuntime` shares the existing admission gate and run coordinator between read workflows and revision operations. `SafRevisionEngine` uses its own mutex; all backend calls receive the exact admitted tree grant and reject remapping. `AndroidSafRevisionBackend` restricts provider and document identity, bounds directory enumeration to 4096 returned cursor rows, bounds bytes and checks current grants before effects. Android provider calls can block outside coroutine cancellation, and provider and external-writer TOCTOU cannot be eliminated by this client. Copy-on-write avoids claiming atomic in-place edit or operating-system compare-and-swap. The source could still change independently, and a provider or another writer can interfere with the destination between checks. The result reports verified observed bytes, not physical durability. No automatic overwrite, delete, retry, rename or rollback of SAF documents. User must check a partial or unexpectedly named copy after an uncertain result. Android-native code has not been compiled against the actual SDK or exercised on a physical device in this release.

A dedicated private `SafRevisionJournal` records only a generated destination name and `PENDING`, `VERIFIED` or `ACKNOWLEDGED` before/after creation. It uses bounded reads, owner-app-private storage and atomic replace of a file with forced data flush. Process restart with pending state fences new previews and writes. The operator must inspect the previous directory and explicitly acknowledge before a new attempt. Acknowledgement does not assert success, repair or delete a file. No source path, raw data, grant or command is persisted. No guaranteed power-loss durability of directory metadata, no recovery of an in-flight provider write and no auto replay. The journal is not an audit history. The operator must retain knowledge of the chosen tree to inspect the recorded destination.

## Future integration ZIP intake (P18)

The tool `scripts/integration_intake.py` rejects malformed or unsafe ZIP packages before any integration. Default invocation **only reads** the archive; output is a deterministic JSON inventory of SHA-256 archive/file digests, paths and expanded sizes. If a trusted digest is available, pin it explicitly. The digest detects mismatch; it is not a signature and no publisher trust is inferred from a ZIP.

```sh
python scripts/integration_intake.py /absolute/path/integration.zip
python scripts/integration_intake.py /absolute/path/integration.zip --sha256 "$EXPECTED_SHA256"
```

Optional staging into a separate, existing owner-private quarantine directory (never the working source tree). Only regular files are created in a new private random-named directory, with mode 0600, no execute bits and no symlinks; directories are owner-private. Returned `staged_not_integrated` is not integration or approval. Do not execute, import, build or copy files from quarantine until manual/engineering review, dependency and license checks, and explicit mapping into existing modules. A failed staging attempt removes its new directory; hard process termination can leave an incomplete quarantine for inspection/cleanup. Parent directories and same-UID operators are trusted. Do not consume staged files before successful report. No live package was integrated.

```sh
mkdir -m 700 "$HOME/omega-quarantine"
python scripts/integration_intake.py /absolute/path/integration.zip --sha256 "$EXPECTED_SHA256" --stage-root "$HOME/omega-quarantine"
```

ZIP32, no encryption or multidisk; stored/deflate only. Limits: 2 GiB input, 4 GiB total uncompressed, 1 GiB per file, 50,000 entries including directories, 32 MiB central directory, ratio at most 1000, depth 32, bounded path and member streaming. Rejected: path traversal, absolute/drive paths, separators and confusing characters, non-NFC names, casefold conflicts, duplicate entries and file/dir conflicts, `.git` components, Windows reserved names/streams, symbolic links/special files, malformed central/local headers and CRC failures. ZIP64/other formats not supported in this bounded intake; if needed, separate bounded implementation must be verified. Payload malware/secret scanning, dependency and license verification, signed releases and runtime compatibility remain distinct review gates. No automatic archive execution or modification of any repository.

## Reproduction

`bash omega-verification/run-saf.sh` runs the real engine and receipt journal on JVM with deterministic provider doubles. `python -m unittest discover -s omega-verification -p 'test_integration_intake.py' -v` exercises real ZIP parsing/quarantine. Full Python and 5 JVM suites are included in `make omega-pre-apk` (never builds APK). Evidence in `omega-verification/evidence/`. Native Android SDK/service/UI checks, physical device E2E, OMAt executor and NPU hardware remain open; the preflight inventory detects the non-exported revision Activity but cannot prove its runtime correctness.
